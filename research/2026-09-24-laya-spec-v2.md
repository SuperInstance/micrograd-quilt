# LayaEvaluator — integration spec v2 (swap-phase revision)

**Repo under study:** `SuperInstance/laya4quilt` @ v0.3.9
**Target:** `quilt-executor` — `executor/evaluator.py`, `executor/decider.py`, `router/fleet_router.py`
**Author:** swap lane (kimi1 play-testing L1's spec against crush's C1 memo) · 2026-09-24
**Lineage:** supersedes `2026-09-24-laya-spec-l1.md`. L1's working design is kept; crush's receipts-doctrine is enforced wherever L1's receipts were claims instead of absences. Changelog at the end maps every change to the memo bullet that forced it.

---

## 0. What laya is (unchanged from L1, re-verified)

One non-autoregressive forward pass over typed `choice`/`score`/`noul` questions; three checkpoints (`english` 421M **max_len 512**, `multilingual` 322M, `typed-decisions` 421M opt-in only); `Router.route()` is pure and weight-free; shipped overconfidence is a fact, not a bug report: **ECE 0.466 as shipped, 0.081 after refit; off-English collapse: Hindi 0.100 accuracy at 0.885 confidence**; score is the weakest primitive (SST-5 0.372); zero-shot typed-decisions sits below majority class.

v2 adds one sentence to this foundation: **proper scoring constrains the scorer's incentive to report its own distribution honestly — it guarantees nothing about whether that distribution is fitted to the world in front of it.** Every design choice below is that sentence operationalized.

## 1. Integration thesis (kept)

Fallback chain per axis, unchanged:

```
laya (typed questions, per-axis) → heuristics (deterministic floor) → LLM judge (optional, within guardrails)
```

Laya is a judge-seat backend, not a replacement for the slow path. Fast proposes, slow disposes, receipts arbitrate.

### 2.1 Question quintet — kept verbatim

Same five questions, same ≤4-level legends, same `score`/`noul` decomposition. One v2 addition per crush's "question-type coercion" rule: **the quintet is executor-owned.** Laya never invents, widens, or re-frames questions; if a task_type cannot be honestly expressed in choice/score/noul frames, that task_type is out of laya's lease scope, full stop. The question builder keeps the ~20-option choice budget documented.

### 2.2 State construction — kept (string only)

String JSON `{"prompt", "output", "context"}` — the dict-state routing quirk (L1 §5 #8) stays mitigated by construction. v2 adds: the **visible span is computed and hashed before predict**, not reconstructed after (§3 visibility).

### 2.3 Axis conversion — kept

Score normalized by `len(criteria)-1`; noul only for `refusal_worthy`; `refusal_worthy ≥ 0.7` routes into the existing refusal guardrails as a prior, not a verdict. v2 adds: confidence is **never** compared against a scalar gate; it goes through `gate_table.lookup(task_type, checkpoint_id, length_bin, season)` (§5).

### 2.4 Per-axis handoff — kept, receipts upgraded

The three-way per-axis handoff (laya serves / heuristics serve / judge overrides within guardrails) is unchanged. What changes is what a handoff writes. The §2.4 metadata block from L1 survives, but every "why" that used to be a prose string is now a **typed absence row** (schema in §3), and laya-level failures book the same typed row on the executor ledger instead of an untyped `REFUSED` with a reason code.

## 3. Typed absences — the exact row payload (replaces REFUSAL)

A refusal is not score 0 or 0.5 — those are claims. Absence must be typed absence. Six types; each is a different operational object and **each updates the bandit differently, mostly by not updating it at all** (§6).

```python
ABSENCE_TYPES = {"noul_ambiguity", "insufficient_context", "ood",
                 "router_failure", "truncation", "timeout"}

ABSENCE_ROW = {
    # --- identity
    "kind": "absence",                      # ledger opcode stays REFUSED-compact; payload is typed
    "absence_type": "truncation",           # one of ABSENCE_TYPES
    "provider": "laya",
    "served_by": "english@convaiinnovations/laya",   # routing reality, not routing intention (kept from L1 §6)

    # --- visibility: "saw" must be provable, not implied
    "visibility": {
        "state_sha256":    "9f2c…",         # hash of the exact string state handed to laya
        "visible_sha256":  "41ab…",         # hash of the span laya's checkpoint actually encoded
        "state_chars":     2911,
        "visible_chars":   1204,            # < state_chars iff truncation fired
        "max_len_tokens":  512,             # checkpoint's context budget
        "span":            [0, 1204],       # character span of the visible prefix
    },

    # --- routing: checkpoint id + router score + alternatives considered
    "routing": {
        "checkpoint_id": "english",
        "router_score":  0.97,
        "alternatives": [
            {"checkpoint_id": "multilingual", "router_score": 0.60,
             "rejected_because": "language_detected_english"}
        ],
        "detection": { ... },               # verbatim Router.route() detection dict (kept from L1 §5 #3)
        "router_confidence_calibrated": False,   # always, until router refit ships (§5)
    },

    # --- trigger: which guard fired and its value
    "trigger": {"guard": "state_length", "value": 2911, "threshold": 3000},
    #   guards in use: state_length, confidence_gate, noul, entropy, ood, checkpoint_unreachable, timeout

    # --- resolvability: refusals are actionable debt, not fog
    "resolvability": {
        "needs": ["state_fit_or_multilingual_checkpoint", "escalate_to_slow_path"],
        "est_extra_cost_ms": 1200,
    },

    # --- linkage: refusal quality is measurable only in pairs
    "parent_receipt_id": None,              # null until the slow path returns
    "escalation": {                         # filled when this absence triggered an escalation
        "escalated_to": "judge",            # judge | slow_receipt | none
        "slow_verdict": 0.73,               # the escalated slow-path verdict (quality or refusal)
        "slow_verdict_kind": "score",       # score | refusal | abstain
        "slow_receipt_id": "fx…",           # hash-chained row id of the slow verdict
        "pair_delta": None,                 # |fast−slow| computed by the lie detector, season stats only
    },

    # --- cost: time-as-first-class, dual-clocked (§8)
    "cost_tick_ms": 33,                     # SIMULATED tick time from the injected clock — chain-authoritative
    "cost_wall_ms": 41,                     # OBSERVED wall latency — advisory (budget/cost accounting only)
}
```

**Type semantics and bandit treatment** (the executor's policy table, not laya's — §7):

| absence_type | meaning | arm update | where the evidence goes |
|---|---|---|---|
| `noul_ambiguity` | honest answer to this task IS a refusal (question's own noul fired) | **none** | refusal prior path (existing guardrails); feeds refusal-rate audit |
| `insufficient_context` | evaluator-side: no `context`/`expected`, or state unbuildable | **none** | `context_risk` LP feature; resolvability debt list |
| `ood` | task outside laya's fitted distribution | **none** | season/shift stats; lease-scope check |
| `router_failure` | wrong or undecided checkpoint, misroute suspected | **none** | router-accuracy lease evidence (§5) |
| `truncation` | visible span < state (checkpoint `max_len` cut) | **none** | difficulty audit; escalation-budget charge if escalated |
| `timeout` | checkpoint unreachable / predict raise | **none** | cost ledger; infra health |

Note what is absent from the "arm update" column: everything. **Refusals never move α/β.** Rationale and the two poison modes in §6.

Every axis handoff and every laya-level failure writes exactly one of these rows (axis rows omit `escalation` until it happens). L1's prose `why` strings survive *inside* `trigger`/`resolvability`, never as the only record.

## 4. Fast-prior wiring into `ThompsonDecider` (kept, two hard rules added)

L1's pseudo-count seeding is kept, including `PRIOR_STRENGTH = 2.0`, the once-per-(context, provider) rule, the youth-discount alignment with `MarginalGainRouter.predicted_gain()`, and the `refusal_worthy ≥ 0.7` seeding skip.

v2 adds two rules crush made non-negotiable:

1. **Arms update only on slow-path ground truth.** Laya's own score of an output never updates the arm that produced the output — that is the arm scoring its own quality, circularity by definition. Laya's score seeds (a prior) and proposes (a feature); realized outcomes — tests, judge verdicts, escalated verdicts — update.
2. **Absence rows are bandit-neutral.** See §3 table; refusal-boundary policy lives in the executor, never in the organ (§7).

Receipt for seeding skip stays: `{"kind": "prior_skipped", "why": "refusal_worthy", "noul": ...}` plus, when the skip came from a typed absence, the full §3 row.

## 5. Calibration — the flat 0.55 gate is dead

L1's §5 #4 said the gate "is a ratchet, not a statistic." Crush's memo makes that operational. The shipped facts are worse than L1's gate assumed: **ECE 0.466 overall as shipped, and the off-English collapse means a confidence of 0.885 can carry 0.100 accuracy** — a scalar gate cannot express "this number is anti-correlated with correctness on this checkpoint." So:

### 5.1 Gate becomes a table, keyed and season-windowed

```python
gate = gate_table.lookup(task_type, checkpoint_id, length_bin, season_id)
```

- **Per-task-type**: quality of "correct" is task-shaped; no pooled gate.
- **Per-checkpoint**: `english`-checkpoint confidence on off-English rows is not merely uninformative, it is *misleading*; rows where routing detection is `language_undecided` or non-English-detection routing to `english` are **escalated, not gated** — the gate does not get a vote on rows the router already flagged.
- **Per-length-bin**: laya's calibration has no length awareness; bins on `visible_chars` (≤512 / ≤1024 / >1024 token-equivalent) until the refit says otherwise.
- **Season-windowed**: a calibration curve is a timestamped artifact. Seasons are executor-defined windows (release weeks, quarterly refactors, upstream model swaps). The hash chain certifies January's honesty in March unless the table is re-fit per season and the refit is itself booked as rows.

### 5.2 What receipts must carry for the refit to be possible

This is the contract. Every laya-served axis row must book, in addition to L1's metadata:

```python
CALIBRATION_PAYLOAD = {
    "task_type":      request.task_type,
    "season_id":      executor.current_season(),
    "checkpoint_id":  "english",             # what served, not what routing intended
    "length_bin":     "512_1024",
    "raw_confidence": 0.71,                  # as returned, uncalibrated
    "probabilities":  [0.61, 0.28, 0.11],    # FULL distribution, not argmax — refit needs the shape
    "criteria_index": 2,                     # which legend level won
    "route_detection": { ... },              # verbatim, for router-accuracy refit
    "truncated":      False,                 # visibility linkage
    "ground_truth":   None,                  # filled by the slow path when it lands; null until then
    "dual_run":       False,                 # §7: lie-detector pairs
}
```

Ground truth arriving late (tests finish, judge returns) **patches the row by receipt-id linkage** — the chain keeps both the before (fast, no label) and after (slow, label) as separate linked rows, never a silent rewrite. Temperature refit runs per (task_type × checkpoint × season) on accumulated rows; `calibrated: true` flips only after refit, per axis, and only for the window it was fit on.

Until the first refit ships, bootstrap gates: English-routed, untruncated, `calibrated: false` → keep 0.55 as a *placeholder with the flag set*; truncated → 0.60 (−0.05 tightening kept from L1); anything routing-ambiguous → escalate. **The 0.55 number is a loading state, not a design.**

### 5.3 Router accuracy is a first-class metric

Misroute → wrong checkpoint scores the row → Thompson would update the wrong arm if refusals updated arms (they don't — §3/§6), and the failure is self-confirming: starved rows never collect the evidence that would correct the router. Countermeasure: every row books `routing.checkpoint_id` + `router_score` + `alternatives`; the lease (§6) requires measured router accuracy per task_type; low-accuracy task_types lose the `english` checkpoint from their lease scope until the refit.

## 6. Bandit policy symmetry and the trust lease

### 6.1 The two poison modes, named

- **never-refuse** (penalize refusals): the organ learns that abstention costs and starts emitting confident noise on rows it cannot see. Locally coherent scores on invisible context — the context-window blindness lie, now with a clean score history.
- **refuse-the-hard** (reward refusals): strategic abstention — the organ escalates exactly the high-uncertainty cases, keeping its measured population clean while the hard rows leak to the slow path.

Both poison MOTH. **Countermeasure: refusal is bandit-neutral.** Absence rows never move α/β (§3). Abstention quality is measured only in *pairs* — a refusal the judge also calls ambiguous is a correct refusal — and pairs feed the lease evidence and the lie-detector statistics, never the posterior. The posterior is fed exclusively by slow-path ground truth on rows the fast arm **scored**.

### 6.2 Trust is a lease, per task_type, with evidence

No task_type gets laya influence on a title. Grant/renew only on all of:

| evidence | bar |
|---|---|
| N hash-chained dual-run pairs where the fast arm **scored** (not refused) | N ≥ 200 per task_type per season, or the task_type stays heuristic-floor |
| tail quantiles of \|Δ\| (fast vs slow), never means alone | p99 \|Δ\| ≤ 0.25; means are banned because they hide gaming |
| refusal rate + refusal-vs-difficulty decorrelation audit | refusal rate ≤ 30%; corr(refusal, realized difficulty) ≈ 0 — **nonzero correlation is the refuse-the-hard tell** |
| current-season calibration curve | refit ECE ≤ 0.10 on this season's own traffic, `calibrated: true` set |
| router accuracy on this task_type | ≥ 95% checkpoint choice matches oracle probe; else `english` checkpoint removed from scope |
| Thompson dominance under time-decay | with half-life decay applied, the real-evidence posterior must outweigh the seeded prior floor; trust expires at season boundary and must be re-earned |

Decay is mandatory: lease weight `w(t) = 2^(-(t - t_grant)/half_life)` multiplies laya's proposal influence (seeding strength, LP utility blend). When `w` decays below the floor, the task_type reverts to heuristics-first without ceremony. A lease is a recurring audit appointment, not a badge.

## 7. Dual-run lie detector — escalation-laundering countermeasures

At 33 ms the fast side of a dual-run is ~free: run a census, not a sample; the estimator's sampling bias disappears. The new lie: the estimator conditions on *declined* escalations, a population the cheap arm itself selects. Escalate exactly the high-uncertainty cases where Δ would be large, keep confident-wrong cases in-house — kept-set mean Δ stays clean, and escalation launders the worst outcomes out of the statistics.

Five countermeasures, all executor-owned (never laya-owned — §9):

1. **Random keep-holdout.** A fixed random fraction (k = 5%) of rows is selected *before* laya answers and may not be escalated. The fast arm must score them; the slow path also runs. This is the un-launderable slice of the population.
2. **Book the fast-arm score on escalated rows too.** The fast arm scores first, the score is recorded, *then* the escalation decision is made. Δ is computed across **both** populations (escalated and kept), and the statistic that gates the lease is Δ over the union — an escalated row whose pre-escalation fast score was confident-and-wrong counts against the arm exactly as if it had stayed home.
3. **Executor-owned thresholds.** Escalation policy, refusal boundaries, and holdout rate live in the executor's config, orthogonal to the arm's self-assessed uncertainty. The arm's confidence may *inform*; it may not *decide*.
4. **Escalation latency charged to the bandit budget.** An escalation is not free: its slow-path latency is booked against the task's bandit budget row, so a strategy of escalate-everything shows up as cost, not as cleanliness. (Charged as budget accounting — still **never** as α/β movement.)
5. **Escalation↔difficulty correlation audit.** Per season, compute corr(escalation/refusal, realized difficulty). Nonzero correlation is the tell for both poison modes; it automatically suspends the lease pending re-audit.

## 8. Time doctrine — two clocks in every receipt

Casey's rule, now a schema invariant: **SIMULATED tick time and OBSERVED wall latency are different quantities and are never conflated.**

- Every receipt carries `cost_tick_ms` (from the injected `Clock`, deterministic, replayable) and `cost_wall_ms` (measured, advisory).
- **The hash chain is the intercellular before/after agreement**: cross-cell ordering, the ledger's TICK/EFFECT linkage, and the dual-run pairing all agree on *tick time*. The chain certifies "fast row preceded slow verdict by N ticks."
- **Wall clock is advisory**: used for cost accounting, budget charging (§7.4), and infra health (`timeout` typing), and explicitly excluded from any correctness or ordering claim. On this box wall is 10–15× inflated by CPU inference; booking wall into the chain would certify hardware mood as doctrine.
- The clock is a constructor-injected parameter (`clock=...`), so simulation runs, replay, and tests run under a scripted clock with identical receipt shapes.

## 9. Never delegate to laya (crush §3, adopted as scope law)

- **Ground-truth/label generation.** The arm scoring its own quality is circularity.
- **Refusal-boundary and escalation-threshold policy.** That is the organ's conflict-of-interest surface (both poison modes live exactly here); the executor owns it.
- **Any verdict whose decisive evidence lives outside the window**: cross-file, cross-commit, semantic-drift judgments, anything security-adjacent or precedent-setting. Laya scores what it sees; the visible-span hash (§3) makes "saw" provable — and proving it saw 2% is precisely why these verdicts escalate.
- **Question-type coercion.** Forcing choice/score/noul frames onto open-ended judgment is a category error laya cannot detect from inside; the executor declares lease scope per task_type and out-of-scope tasks never reach laya.

Also kept from L1 §6: one ledger, not two. laya's fnv1a-32 QuiltLedger is not introduced as a second book; absence/decision content rides in the executor ledger's existing rows via metadata; `served_by` records routing reality.

## 10. Rollout order (L1's ladder, re-gated)

1. `LayaEvaluator` behind the judge seam, metadata-only — shadow mode. **Gate to next step requires:** §5.2 calibration payload booking cleanly for one full season window.
2. Typed absence rows on the ledger (`kind: "absence"` payload under the existing REFUSED opcode). **Gate:** all six absence types observed at least once in shadow traffic, or the season ends — whichever first; then refit #1 ships and `calibrated: true` starts appearing per axis.
3. Fast-prior seeding for `ThompsonDecider`, only for task_types holding a §6.2 lease; everything else stays heuristic-floor.
4. LP feature hooks + random keep-holdout (5%) dual-runs + escalation-laundering audit live. Lease renewal becomes a cron, not a ceremony.
5. Temperature refit per (task_type × checkpoint × season) on accumulated traffic — the standing fix for the shipped ECE 0.466, now measured instead of assumed.
